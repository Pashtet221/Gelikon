# Промпт для WordPress Bridge: заполнение ACF страницы «Гарантия и возврат»

Скопируйте весь блок ниже в Codex, подключённый к сайту через WordPress Bridge.
Промпт переносит в ACF-поля значения, которые сейчас выводятся PHP-шаблоном как
fallback, чтобы контент был виден клиенту в админке и редактировался там.

```text
Работай с production-сайтом через WordPress Bridge. Не изменяй файлы темы, не
добавляй новые fallback-значения в PHP и не создавай новую страницу. Найди
существующую WordPress-страницу, которой назначен шаблон
`page-warranty-returns.php`, и заполни её ACF-поля значениями, которые сейчас
выводит шаблон страницы «Гарантия и возврат» как fallback.

Сначала выполни безопасную проверку: должна существовать ровно одна страница с
этим шаблоном, её ID должен быть ненулевым, а функция ACF `update_field` должна
быть доступна. Если проверка не пройдена — ничего не записывай и сообщи об
ошибке. Затем через WP-CLI WordPress Bridge выполни следующую команду из корня
установки WordPress:

Не назначай изображения полю `icon` внутри преимуществ: в fallback шаблона нет
медиафайлов, поэтому нельзя выдумывать ID вложений. Пустые значения `icon` в
трёх строках повторителя оставь как в команде. Не перезаписывай заголовок
страницы, slug, статус, контент Gutenberg или назначенный шаблон.

После записи прочитай через ACF все 13 полей из массива `$fields`. Покажи ID,
заголовок и URL страницы, а затем выведи короткий отчёт «ключ поля → сохранённое
значение» (для повторителя покажи три строки с `title` и `text`). Отдельно
подтверди, что значения теперь хранятся в данных страницы и видны в блоке
«Гарантия и возврат — контент страницы» в админке, а не берутся из fallback в
PHP. Если какое-либо сохранённое значение отличается от заданного, явно укажи
это и не объявляй задачу полностью выполненной.
```

Команда использует **ключи ACF**, а не только имена полей. Благодаря этому ACF
создаёт служебные ссылки `_имя_поля → field_...`, и сохранённые значения
корректно появляются в редакторе страницы WordPress.
